Introdução ao SQL

Bem-vindo ao SQL Bolt, uma série de lições e exercícios interativos projetados para ajudar você a aprender SQL diretamente no seu navegador.

O que é SQL?

SQL, ou Structured Query Language, é uma linguagem projetada para permitir tanto o conteúdo técnico quanto o conteúdo lógico com praticidade e clareza. Ela é usada para consultar, manipular e transformar dados em um banco de dados relacional.

Você sabia?

Existem muitos bancos de dados SQL populares, incluindo SQLite, MySQL, PostgreSQL, Oracle e Microsoft SQL Server. Todos eles suportam o padrão da linguagem SQL, e o que existe sete seria o básico que você precisa aprender.

Bancos de dados relacionais

Antes de aprender a sintaxe SQL, é importante ter um modelo do que um banco de dados relacional representa. Em um banco de dados relacional, as informações são organizadas em tabelas (bidimensionais), com linhas e colunas. Cada coluna possui um tipo de dado e cada linha representa um registro. Esse modelo facilita a organização e a busca por dados.

Por exemplo, em uma tabela de veículos, cada veículo teria uma linha com dados sobre marca, modelo, número de portas, tipo e ano.

Normalização

A normalização é um processo essencial para organizar os dados de um banco de dados, eliminando redundâncias e reduzindo inconsistências. Em vez de repetir informações em diversas tabelas, a organização é feita de forma lógica para manter a integridade dos dados.

Formas normais

As formas normais são regras usadas na normalização de bancos de dados relacionais. Elas ajudam a reduzir a repetição de informações e a evitar anomalias de inserção, atualização e exclusão. A seguir, são apresentadas a Segunda Forma Normal (2FN) e a Forma Normal de Boyce-Codd (FNBC), com exemplos práticos.

  • 1FN: elimina grupos repetidos e garante que cada campo tenha apenas valores atômicos.
  • 2FN: elimina dependências parciais de atributos não primos em relação às chaves candidatas.
  • 3FN: trata dependências transitivas que podem gerar redundância.
  • FNBC (BCNF): exige que todo determinante de uma dependência funcional não trivial seja uma superchave.

Segunda Forma Normal (2FN)

Uma tabela está na Segunda Forma Normal quando já atende à Primeira Forma Normal e nenhum atributo não primo depende apenas de uma parte de uma chave candidata composta. Esse tipo de problema é chamado de dependência parcial. Ele pode fazer com que a mesma informação seja repetida em várias linhas e provoque inconsistências quando os dados são alterados.

Exemplo: considere uma tabela de matrículas cuja chave é a combinação de ID_Aluno e ID_Curso.

Tabela original: Matrículas

ID_AlunoID_CursoNome_AlunoNome_Curso
1101AnaBanco de Dados
1102AnaProgramação
2101PedroBanco de Dados

Nesse exemplo, Nome_Aluno depende somente de ID_Aluno, e Nome_Curso depende somente de ID_Curso. Como a chave é composta pelos dois identificadores, essas dependências são parciais.

Como corrigir: separar as informações em três tabelas:

  • Alunos: ID_Aluno, Nome_Aluno.
  • Cursos: ID_Curso, Nome_Curso.
  • Matriculas: ID_Aluno, ID_Curso, usando os identificadores como chave composta e referências às tabelas correspondentes.

Com essa divisão, o nome do aluno e o nome do curso são armazenados uma única vez nas respectivas tabelas. A 2FN reduz redundâncias e facilita a manutenção e a consistência dos registros.

Forma Normal de Boyce-Codd (FNBC)

A Forma Normal de Boyce-Codd, também chamada BCNF em inglês, é uma regra mais rigorosa que a Terceira Forma Normal. Uma tabela está na FNBC quando, para toda dependência funcional não trivial X → Y, o conjunto de atributos X é uma superchave. Em outras palavras, todo atributo ou conjunto de atributos que determina funcionalmente outros atributos deve ser capaz de identificar unicamente as linhas da tabela.

Exemplo: imagine uma tabela que registra professor, disciplina e sala. Considere a regra de negócio de que cada professor usa uma única sala, embora possa ministrar várias disciplinas.

Tabela original: Aulas

ProfessorDisciplinaSala
AnaMatemáticaA101
BrunoHistóriaB202
AnaFísicaA101

Se a chave candidata for (Professor, Disciplina), a dependência Professor → Sala viola a FNBC: professor determina a sala, mas Professor sozinho não é superchave, pois um professor pode aparecer em mais de uma disciplina.

Como corrigir: decompor a tabela em duas relações:

  • Professores: Professor, Sala.
  • Aulas: Professor, Disciplina.

Assim, a sala fica registrada uma vez por professor, e a tabela de aulas mantém a relação entre professor e disciplina. Essa decomposição é válida para as regras de negócio assumidas no exemplo.

Diferenças entre 2FN e FNBC

Critério2FNFNBC
ObjetivoEliminar dependências parciais.Garantir que determinantes de dependências funcionais não triviais sejam superchaves.
FocoAtributos não primos dependentes de parte de uma chave candidata composta.Dependências funcionais que podem envolver diferentes conjuntos de atributos.

Conclusão

A 2FN e a FNBC contribuem para a construção de bancos de dados mais organizados e consistentes. A 2FN elimina dependências parciais de atributos não primos em relação às chaves candidatas, enquanto a FNBC aplica uma regra mais rigorosa às dependências funcionais. A escolha da decomposição deve sempre considerar as chaves e as regras de negócio do sistema, para reduzir redundâncias sem perder informações importantes.
